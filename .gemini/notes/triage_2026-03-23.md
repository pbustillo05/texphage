# Triage Report: 2026-03-23

This report outlines the highest ROI improvements for `texphage`, based on analysis of the current codebase state (`BUGS.md`, `TODO.md`, `macros.md`, `inclusions.md`) and external evidence of usage on arXiv.

## Top 3 High-ROI Candidates

### 1. Core TeX Primitives: `\csname` and `\expandafter`

- **Item**: `macros.md`: `\csname ... \endcsname` and `\expandafter`
- **Why now**: This is a TeX primitive. Its absence is a fundamental gap in the parser's understanding of LaTeX. Many complex packages and user macros rely on this for metaprogramming. Supporting it would unlock a long tail of complex macro definitions that are currently invisible to `demacro.py`. It's the highest leverage point for improving raw parsing power.
- **Confidence**: HIGH
- **Test to verify**:
  ```latex
  \documentclass{article}
  \makeatletter
  \newcommand{\definecommand}[1]{%
    \expandafter\def\csname#1\endcsname{Hello, #1!}%
  }
  \definecommand{world}
  \begin{document}
  \world
  \end{document}
  ```
- **Blocker for promotion**: The pipeline should produce `Hello, world!` in the body. If `\world` remains unexpanded, the test fails, and this should be a HIGH priority TODO.

### 2. Modern LaTeX: `xparse` Advanced Argument Specifiers

- **Item**: `macros.md`: `xparse` advanced argument specifiers
- **Why now**: `xparse` is a core LaTeX package. The current implementation only supports a fraction of its argument types (`m, o, O, s, t`). The unsupported specifiers (like `r`, `R`, `d`, `v`, `+m`) are common in modern packages. Supporting them would significantly increase the number of `\NewDocumentCommand` definitions we can correctly parse, reducing `pattern_mismatch` errors.
- **Confidence**: HIGH
- **Test to verify**:
  ```latex
  \documentclass{article}
  \NewDocumentCommand{\testcmd}{v}{Verbatim: #1}
  \begin{document}
  \testcmd|some_content|
  \end{document}
  ```
- **Blocker for promotion**: The pipeline should produce `Verbatim: some_content` in the body. If `\testcmd|some_content|` remains unexpanded, the test fails. This demonstrates a gap in parsing verbatim (`v`) arguments. This should be a HIGH priority TODO.

### 3. Graphics and Figures: `pgfkeys` Support (`\tikzset`)

- **Item**: `TODO.md` / `macros.md`: `pgfkeys` Support (`\tikzset`)
- **Why now**: TikZ is arguably the most common and important graphics package on arXiv for math and physics. `\tikzset` is the primary mechanism for defining custom styles and commands within TikZ. Not parsing these definitions means we are failing to capture critical information for rendering figures, leading to major visual and semantic discrepancies.
- **Confidence**: HIGH
- **Test to verify**:
  ```latex
  \documentclass{article}
  \usepackage{tikz}
  \tikzset{my style/.style={draw=red, thick}}
  \newcommand{\mybox}[1]{\tikz[baseline]\node[my style, rounded corners]{#1};}
  \begin{document}
  Here is a \mybox{styled box}.
  \end{document}
  ```
- **Blocker for promotion**: The pipeline should expand `\mybox` into its underlying `\tikz` command. A failure to expand `\mybox` at all, or leaving `my style` unhandled, would justify adding this as a HIGH priority TODO. The goal is to expand macros that *use* TikZ styles; expanding the styles themselves is a secondary, harder goal. This test checks the first part.

## Uncertain / Lower Priority

- **`etoolbox` patching**: `\patchcmd`, `\pretocmd`, `\apptocmd` are powerful but very difficult to model with static analysis. ROI is high, but implementation complexity and risk of incorrectness are also very high.
- **Minimal `\usepackage` list**: This is a great enhancement for canonicity but lower priority than fundamental parsing gaps. This should be tackled after the major correctness gaps are closed.
- **`import` package completion**: `\includefrom` and `\subincludefrom` are good to have for completeness but are less common than the core `\import`/`\subimport`.
